# Updating the yearly figures

All CPF figures live in `data/*.yaml`. The code reads them from `data.js`, which is
generated - never edit `data.js` by hand.

## Workflow (every update)

1. Edit the YAML file(s) listed below.
2. `node build.js` - regenerates `data.js`.
3. `node test.js` - must pass. It pins the base year, so it behaves the same in any
   calendar year. If the new figures intentionally move results, refresh the golden
   numbers in `test.js` and call that out in the PR.
4. Open `index.html` in a browser and sanity-check the headline numbers.
5. One commit / PR with the YAML edits and the regenerated `data.js`.

## It is 2030 - what to check

### data/cpf_rules.yaml (check yearly)

- `retirement_sums.announced`: add every newly announced FRS as
  `- year: YYYY` / `frs: <amount>` rows. Keep old rows. Years after the last announced
  row grow at the form's "Retirement Sum growth" rate; BRS and ERS are derived from the
  FRS automatically, and the form label ("growth after ...") follows the last row.
- `interest`, `extra_interest`: confirm against cpf.gov.sg; they rarely change.
- `ages`: statutory; assume unchanged.

Source: cpf.gov.sg - retirement sums page and interest rate pages.

### data/cpf_life_2026.yaml (when CPF republishes the LIFE payout tables)

- `table.points`: replace with the current Standard Plan, male, payout-from-65 rows
  (RA balance and monthly payout).
- `escalating_plan`: copy both FRS-balance payouts (Standard and Escalating) from the
  same publication; confirm `annual_increase_pct` (2%).
- `adjustments`: confirm `female_discount_pct` (about 5) and
  `deferral_uplift_pct_per_year` (about 6). Re-derive `table_calibration_factor` if the
  published FRS payout no longer equals the interpolated table value times this factor.
- If the table year changed, rename the file to `cpf_life_<year>.yaml` and update the
  filename in `build.js` and in `README.md`.

Source: cpf.gov.sg - CPF LIFE payout table and the Retirement Payout Planner.

### data/default.yaml (only if the examples should change)

- Form defaults, shown on first load. `age_now` values are ages, not birth years, so
  they stay correct as years pass - no annual edit needed.

## Leave alone

- `model.js` and `index.html` logic - touch only if a CPF rule itself changed, not just
  the values.
- `data.js` - generated by `node build.js`.
